- **Instant acknowledgement / "thinking" placeholder (issue #47).** Native v3 typing (`POST /api/v3/chats/{chat_id}/activities`) is a separate capability (learning 074); the placeholder remains a visible in-chat substitute that posts a lightweight message (e.g. `💭 …`) immediately on inbound, then EDIT it in place into the final agent reply — exactly one message, no duplicate. Editing a message needs the `ZohoCliq.Messages.UPDATE` scope, which `client_credentials` cannot obtain, so the placeholder flow is only usable when a `refreshToken` is configured; the gate is `thinking.mode === "placeholder"|"card"` plus a configured `refreshToken`. When streaming preview is also on, the placeholder is the same draft the live-edit path then grows in place (issue #175) — one progress surface, never two. The placeholder ref `{messageId, chatId?}` is threaded into `createLiveEditDeliver` as `initialDraft`; for group posts the send response carries only `{id}` (no chatId), so the chat id is resolved lazily via `CliqClient.resolveChannelChatId` on the first edit (cached per client — a `draftChatIdResolved` flag prevents redundant resolution calls when the channel is unresolvable). The "no stray `💭 …`" contract: when the edit cannot be performed cleanly (chat id unresolvable, edit API rejects, first-block overflow that can't be chunked into the draft) the placeholder is DELETED via `CliqClient.deleteMessage` and the reply is sent as a fresh message — a failed placeholder post/edit is swallowed + logged and never breaks or delays the turn. The no-reply case (the agent turn threw, or the dispatcher flushed zero blocks) is handled by wrapping `runtime.channel.inbound.run` in a `try/finally`: the `finally` checks `getLiveEditPlaceholderConsumed(deliver)` (exposed by `createLiveEditDeliver`, true iff a `deliver` call resolved the placeholder's fate) and, when the placeholder is still untouched, edits it into `thinking.failureText` (optional; e.g. `⚠️ No reply generated.`) or DELETES it when `failureText` is unset — so a stray `💭 …` never lingers. The `thinking` config (`{ mode: "off" | "placeholder", text, failureText? }`) lives at `channels.cliq.thinking` and now defaults to `{ mode: "placeholder", animate: "dots" }`; `applyAccountConfig` writes it via `writeField("thinking")` so `openclaw configure` can provision it.
