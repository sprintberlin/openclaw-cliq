- **Inbound quote / reply context is a plugin-owned concern.** The generated Message handler receives the **new** message as a string and does not forward a parent reference or text. Whether Cliq exposes a reply identifier to that handler remains unverified. The parser tolerates `parent` / `quoted` / `parent_message` / `quoted_message` / `reply_to_message` at the payload root or under `message`, merging every source — `messageId` from `message.reply_to` + `text`/`sender` from a sibling object. When only the id is present, the plugin best-effort fetches the parent via `GET /api/v2/chats/{chatId}/messages` (matching by `messageId` in the recent-messages list; the plugin requires a refresh token and `ZohoCliq.Messages.READ` for this read). That history read can fail for some active DM lanes (see learning 169), so recovery must degrade and log only status plus allow-listed code. The quote text is prepended to the agent envelope `body` (the legacy `finalizeInboundContext` finalizer has no dedicated `ReplyToText` param consumed by the runtime — only `ReplyToId`/`ReplyToIdFull` are standard; the plugin appends `ReplyToMessageId`/`ReplyToText`/`ReplyToSenderId`/`ReplyToSenderName` for telemetry/correlation). A reply to the bot in a group sets the `reply_to_bot` / `quoted_bot` implicit-mention kinds (already wired in `resolveCliqMentionFacts` via the `opts` the dispatcher now passes) so a group reply to the bot is admitted without a fresh @mention.
